# 麻雀プラットフォーム フルリニューアル設計（2026-11-15）

クライアント案件。PPPoker型（クラブ制・招待制・ダイヤ／クラブポイント）のリーチ麻雀。現金のやり取りはない。
キャラクターは使わない。質感の目標は商用アニメ調麻雀の水準（オリジナルデザイン）。和了・放銃・ツモの演出は豪華に。

旧コード（`apps/mobile` `apps/server` `apps/admin` `packages/mahjong-engine` `packages/shared` と旧 `supabase/`）は
監査の結果すべて作り直す。**新コードが揃うまで旧コードは消さない**（削除は山本さんの確認後）。

## 構成

| 場所 | パッケージ | 役割 |
|---|---|---|

| `tools/oracle` | — | 点数計算の外部の正解（Python `mahjong` 1.4.0）と突き合わせる検算 |

## 権威の所在

- **対局の正は対局サーバーのメモリ上**。クライアントは「自分に見える情報（view）」と「出来事（event）」だけを受け取る。山・他家の手牌・乱数の種はクライアントに出ない。
- 乱数は `crypto` 由来の256bitの種。局ごとに山のSHA-256を先に公開し、終局後に種を公開する（後から検証できる）。
- DBに書くのは、対局の開始・各局の結果・終局（順位・精算）・牌譜。対局中の1手ごとにはDBを触らない。
- 精算（ポイント移動・Fee）は終局時にサーバーが service_role で1つのRPC（1トランザクション）を呼ぶ。

## エンジン（`@mj/core`）の形

- 牌: `kind` 0..33（萬1-9, 筒1-9, 索1-9, 東南西北白發中）、`id` 0..135（`kind = id >> 2`）。赤は 5m/5p/5s の id%4==0。
- `Round`（1局）は「いま誰の何を待っているか」を明示的に持つ:
  - `phase: 'draw' | 'discard' | 'claim' | 'end'`
  - `claim` では、反応できる全員の選択肢 `pending[seat]` を出し、**全員の回答が揃ってから**優先順位で解決する（ロン＞ポン/カン＞チー。ロンは複数可＝ダブロン）。
  - 時間切れはサーバーが「既定の行動（パス／ツモ切り）」を代わりに投入する。エンジン自体は時計を持たない。
- すべての入力は検証する（手牌にある牌か、面子として成立するか、喰い替え、リーチ後の制約、フリテン、役の有無）。不正な入力は状態を変えずにエラーを返す。
- `Game`（半荘/東風）は局の進行・連荘・本場・供託・終了条件・ウマ/オカを持つ。
- 出力は `events[]`（全情報）と `viewFor(seat)`（秘匿済み）。再接続時は view を丸ごと送り直す。

## 既定ルール（卓ごとに設定で変更可）

4人: 25000点持ち30000点返し／喰いタンあり／赤3枚／一発・裏ドラ・槓ドラ・槓裏あり／ダブロン・トリロンあり／
途中流局あり（九種九牌・四風連打・四槓散了・四家立直）／流し満貫あり／数え役満あり／切り上げ満貫なし／
フリテン（河・同巡・リーチ後）／喰い替え禁止／責任払い（大三元・大四喜）／トビあり（0点未満）／
西入あり（30000点未満でサドンデス）／オーラス親のアガリやめ・テンパイやめ／リーチは1000点以上かつ山4枚以上／
暗槓は即めくり・明槓/加槓は打牌後めくり／国士の暗槓ロンあり／ウマ既定 +15/+5/-5/-15（設定可）。

3人: 35000点持ち40000点返し／萬子2-8なし（108枚）／チーなし／北抜き（抜きドラ・嶺上から補充・抜いた北はロン可）／
ツモ損あり／ウマ既定 +15/0/-15。

## 通信（WebSocket・JSON）

クライアント→サーバー: `hello{token, tableId}` / `action{seq, ...}` / `ready` / `stamp{id}` / `ping`
サーバー→クライアント: `welcome{seat, view}` / `events{events[], view}` / `prompt{options, deadline}` / `error{code}` / `result` / `pong`

- `prompt.deadline` は**時刻**（サーバー時計のms）。クライアントは手元で秒を減らす。
- `action.seq` は直前の `prompt` の番号。古い番号は捨てる（二重送信・遅延送信の無害化）。
- 切断した席は、持ち時間切れでツモ切り/パスの自動処理。再接続で view を送り直して続行。

## クラブと経済（PPPoker型）

ロール: L1 プラットフォーマー／L2 クラブオーナー／L3 エージェント／L4 プレイヤー。
- **ダイヤ**: プラットフォーマーがオーナーに発行する運営通貨。クラブの維持・卓の開設に消費。
- **クラブポイント**: クラブ内だけの点数。オーナー/エージェントが配布・回収。対局の精算に使う。
- **Fee**: 対局ごとにクラブが徴収（設定は率または固定、勝者から/全員から）。
- 台帳は追記のみ（UPDATE/DELETE不可）。残高は台帳の合計と一致させる。
- 招待: クラブID＋招待コードで申請→オーナー/エージェントが承認。プレイヤーはエージェントの配下に付く。

## 工程と合格ライン

1. エンジン — 外部の正解との突き合わせ（点数）＋場面テスト（進行）＋自動対戦での不変条件（牌の総数・点数の総和・停止しない）
2. 対局サーバー — ボット4人/人間混在で半荘が完走、同時入力・切断・再接続のテスト
3. 卓の画面・牌・演出・音 — ブラウザで1半荘を最後まで操作できる
4. ロビー・クラブ・招待
5. ダイヤ・ポイント・Fee・管理画面
6. 通しプレイでUI/UXを直し、プレイ動画を保存
